
# 🧪 Packet Tracer — Navegación por IOS y configuración de comandos

## 🎯 Objetivo

Practicar el uso de la **CLI de Cisco IOS**.
---

## 🔌 Acceso mediante consola

Conecté `PC1` al switch `S1` utilizando un **cable de consola**:

<img width="535" height="455" alt="image" src="https://github.com/user-attachments/assets/8c0afac2-347b-485b-b0cf-c84a94b46f77" />


Desde `PC1 → Desktop → Terminal` inicié una sesión de terminal.

La configuración utilizada fue:

| Parámetro | Valor |
|---|---|
| Bits por segundo | `9600` |
| Data Bits | `8` |
| Parity | `None` |
| Stop Bits | `1` |
| Flow Control | `None` |

Al iniciar la sesión apareció:

```text
S1>
```

El símbolo `>` indica que estaba en **modo EXEC de usuario**.

---

## ❓ Ayuda contextual de IOS

Utilicé `?` para consultar los comandos disponibles:

```text
S1> ?
```

Entre los comandos disponibles, identifiqué:

```text
connect
```

También probé la ayuda escribiendo solamente una parte del comando:

```text
S1> t?
```

Resultado:

```text
telnet
terminal
traceroute
```

Al especificar un carácter más:

```text
S1> te?
```

las posibilidades se redujeron a:

```text
telnet
terminal
```

Esto permite buscar comandos sin necesidad de conocerlos completamente.

---

## ⌨️ Autocompletado con `Tab`

Probé el autocompletado escribiendo:

```text
S1> en
```

y presionando `Tab`.

IOS completó automáticamente:

```text
S1> enable
```

Esto funciona porque `en` identifica de forma única al comando `enable`.

En cambio, `te` no puede completarse automáticamente porque existen varias posibilidades:

```text
telnet
terminal
```

---

## 🔐 Acceso al modo EXEC privilegiado

En la ayuda, `enable` aparecía descrito como:

```text
enable    Turn on privileged commands
```

Ejecuté:

```text
S1> enable
```

y el prompt cambió:

```text
S1>
 ↓
S1#
```

El símbolo `#` indica que ingresé al **modo EXEC privilegiado**.

Al explorar los comandos que comienzan con `C` encontré:

```text
clear
clock
configure
connect
copy
```

En total, **5 comandos**.

---

## ⚙️ Acceso al modo de configuración global

Desde EXEC privilegiado ejecuté:

```text
S1# configure
```

IOS mostró:

```text
Configuring from terminal, memory, or network [terminal]?
```

Acepté la opción predeterminada `[terminal]` presionando `Enter`.

El prompt cambió:

```text
S1#
 ↓
S1(config)#
```

Esto indica que ingresé al **modo de configuración global**.

Para regresar el comando:

```text
exit
```

# 🕒 Configuración del reloj

## Consultar el reloj

Desde EXEC privilegiado ejecuté:

```text
S1# show clock
```

Inicialmente obtuve:

```text
*2:38:21.326 UTC Mon Mar 1 1993
```

Por lo tanto, el switch tenía configurado inicialmente el año **1993**.

---

## Explorar `clock`:

Al ejecutar solamente:

```text
S1# clock
```

IOS respondió:

```text
% Incomplete command.
```

El comando existe, pero necesita información adicional.

Utilicé entonces:

```text
S1# clock ?
```

y continué explorando su sintaxis:

```text
S1# clock set ?
```

Luego:

```text
S1# clock set 15:00:00 ?
```

La ayuda contextual permitió descubrir progresivamente los parámetros necesarios para completar el comando.

Finalmente configuré:

```text
S1# clock set 15:00:00 31 Jan 2035
```

y verifiqué el resultado con:

```text
S1# show clock
```

# ⚠️ Mensajes de error de IOS

Durante la práctica también probé comandos incorrectos o incompletos para observar cómo responde IOS.

### Comando ambiguo

```text
S1# cl
% Ambiguous command: "cl"
```

`cl` puede corresponder a más de un comando, como:

```text
clear
clock
```

Por eso IOS no puede determinar cuál quiero ejecutar.

### Comando incompleto

```text
S1# clock
% Incomplete command.
```

IOS reconoce el comando, pero necesita **más parámetros**.

### Entrada inválida

Al introducir valores que no pertenecían al rango aceptado, IOS mostró:

```text
% Invalid input detected at '^' marker.
```

El símbolo:

```text
^
```

indica aproximadamente el punto donde IOS detectó la entrada incorrecta.

---




cl
```

Esta práctica me permitió utilizar la ayuda de IOS para **descubrir la sintaxis de los comandos**, navegar entre diferentes modos y reconocer los principales mensajes que aparecen cuando un comando es ambiguo, incompleto o contiene una entrada inválida.
